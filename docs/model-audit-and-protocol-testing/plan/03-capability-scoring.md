# 通用模型能力评分

## 1. 目标与原则

能力评分用于量化某个渠道上的某个模型在版本化任务集中的表现，不代替身份检测。相同声明模型可以身份相符但能力较低，也可能因思考档位、协议转换、上下文截断或服务限制出现差异。

首期结果名称为“能力指数”，不使用 IQ。评分对象固定为渠道 ID、协议、请求模型、实际模型、思考档位、任务集版本和执行轮廓。

## 2. 首期维度

| 维度 | 主要任务形态 | 优先判分方式 |
| --- | --- | --- |
| 数学与逻辑 | 参数化短题、多步约束、可验证结论 | 精确答案、容差数值、证明关键点 |
| 代码生成与理解 | 小函数、缺陷定位、输出预测 | 沙箱测试用例、AST/结构检查、精确结果 |
| 指令遵循与结构化输出 | 多约束文本、JSON Schema | Schema、字段约束、禁止项检查 |
| 工具调用 | 函数选择、参数构造、多步调用 | 工具名、参数 Schema、调用顺序和最终答案 |
| 长上下文与多轮一致性 | 针对性检索、状态保持、冲突信息 | 目标事实、引用位置、跨轮状态断言 |
| 知识与事实性 | 稳定事实、给定材料内问答 | 标准答案和证据匹配，避免依赖易变化新闻 |
| 重复稳定性 | 同题多次、等价改写 | 正确率分布、方差、矛盾率 |

延迟、token、估算成本和错误率作为服务效率指标独立展示，不直接伪装成能力。汇总页可以并列给出能力、稳定性、性能和成本摘要。

## 3. 任务包合同

每个任务包含：稳定 ID、版本、维度、难度标签、适用模态/协议、输入生成器、随机种子、思考档位要求、最大 token、预期输出合同、判分器、超时、重复次数和泄漏风险等级。

任务分为：

- 固定公开任务：便于人工复核，不承担主要抗污染能力。
- 参数化任务：按种子生成等价实例和确定答案。
- 保留任务：只在后端保存必要定义，报告不暴露完整答案。

题目内容与判分器必须版本化。改变答案、难度或评分规则需要新版本，历史报告继续引用原版本。

## 4. 判分与归一化

首期优先使用无需模型裁判的客观评分：精确匹配、集合比较、数值容差、JSON Schema、测试用例、工具调用结构和显式断言。确需语义判分的任务必须使用结构化 rubric，保留“无法自动判定”状态，且不能让被测模型自评。

计算链：

1. 判分器产生每题原始分、错误分类和证据。
2. 同一维度按任务难度和版本化权重汇总为 0-100 分。
3. 通过重复样本或 bootstrap 计算维度置信区间。
4. 总能力指数按版本化维度权重汇总，并同时展示覆盖率。
5. 题目跳过、协议不支持或样本不足会降低覆盖率和置信度，不能按零分静默处理。

当积累足够跨模型、跨渠道校准样本后，可引入 IRT 或分层模型估计题目难度和模型能力；首期不能在缺少校准数据时虚构 IRT 参数。原始题目结果必须保留，使未来更换统计模型时可重新计算而不重跑全部请求。

## 5. 公平比较

- 只有任务包版本、协议能力、思考档位和主要运行设置兼容时，才允许直接排序。
- 对不支持某项能力的协议，显示“不适用”或单独评分，不用零分惩罚整个模型。
- 总分展示覆盖率；覆盖率未达阈值时标记为临时结果。
- 默认模型解析结果必须入报告，避免渠道默认模型变化后继续沿用旧标签。
- 长上下文、工具和多轮任务分别记录渠道是否经过协议转换，防止把转换器缺陷误判为模型能力。

## 6. 运行档位

为控制费用，首期提供版本化运行预设：

- 快速：少量代表题，用于回归观察，不生成最高等级结论。
- 标准：覆盖全部核心维度和最低重复次数，可生成正式能力报告。
- 深入：提高重复次数、难度和长上下文覆盖，用于人工选择的专项比较。

预设只决定默认任务和预算，管理员仍可在合理范围内选择策略和样本。运行前显示估算请求数和 token 上限；超过任务预算必须停止并给出部分结果，不能静默继续消费。

## 7. 输出

能力报告至少展示：总指数、置信区间、覆盖率、各维度分数和区间、题目数量、成功/失败/跳过数、稳定性、模型与档位快照、任务包及判分器版本、usage、延迟和估算成本。

详情允许下钻到单题的脱敏输入摘要、输出、判分断言和错误分类。HTML 报告默认不导出保留题完整答案。

## 8. 验收条件

- 至少覆盖七个首期维度，每个维度有客观可模拟验证的任务合同。
- 分项和总分均包含覆盖率与置信区间，样本不足不会显示虚假精确分数。
- 修改题目或判分器生成新版本，历史结果保持可解释。
- 模拟优秀、部分正确、随机、格式错误和协议不支持输出得到预期分数与状态。
- 能力、稳定性、性能、成本和身份风险在数据及 UI 中保持分离。
