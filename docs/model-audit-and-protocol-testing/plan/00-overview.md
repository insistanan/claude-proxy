## 1. 问题与 Outcome

现有快速测试主要把网络可达或 `/v1/models` 成功等同于模型可用，前端又分别拼装简化请求，无法可靠覆盖 Responses typed SSE、Codex 请求轮廓、不同协议的思考参数和失败终态。演武台与快速测试没有共享完整的协议执行合同，导致渠道在真实客户端可用、在管理界面却无响应或无法诊断。

项目还缺少独立的模型审计能力，无法回答渠道是否返回所声明的 GPT 模型、是否固定替换或随机混用，以及同一模型在不同渠道上的能力是否明显降级。

完成后，管理员能够选择一个或多个具体渠道，以手动或低频定时方式执行协议真实的模型请求；系统分别给出 GPT 身份、混用风险、通用能力、稳定性、性能和成本结果，并在渠道列表、详情页和可选 HTML 报告中提供可复核证据。快速测试和演武台使用同一套后端协议执行器，能够明确区分成功、失败、不完整、断流、协议不支持与内容为空。

## 3. 关键概念

| 概念 | 定义 | 边界与真相源 |
| --- | --- | --- |
| 渠道目标 | `channel_id + channel_kind` 唯一定位的上游配置 | 使用现有稳定渠道 ID，不使用可变化的数组下标持久化关联 |
| 请求目标 | 渠道目标、请求协议、请求模型、实际解析模型、思考档位和请求轮廓的冻结快照 | 报告创建后不随渠道默认配置变化 |
| 快速测试 | 单次低成本、自然、协议真实的正常模型请求 | 不是身份审计，也不是 `/models` 测活 |
| 演武台 | 用户可编辑输入和协议选项的诊断工作台 | 允许展示脱敏请求和协议时间线，不承担批量审计统计 |
| 探针策略 | 声明适用范围、请求、归一化、判分、样本要求和版本的检测单元 | 未满足适用条件必须显式跳过或报错 |
| 身份结论 | 多个独立信号对声明模型是否相符的概率性判断 | 不是密码学证明；不得由单一 Juice 值直接下结论 |
| 混用结论 | 对样本来自一个或多个潜在模型分布的估计 | 与偶发质量波动、超时和协议错误分开 |
| 能力指数 | 版本化任务集上的 0-100 量化结果及置信区间 | 不称 IQ；不同题库版本不能直接混比较 |
| 正式结论 | 样本、基线、策略版本和协议合同均满足最低要求的结果 | 样本不足只能展示临时观察 |

## 5. Goals

1. 建立统一、可扩展、可诊断的渠道请求执行器，重构全部快速测试和演武台。
2. 建立策略注册、版本、配置、基线、样本和报告合同。
3. 对 GPT-5.6 Sol 实现多信号身份检测，对固定替换、随机或比例混用给出带置信度结论。
4. 对 GPT、Claude、Gemini 等模型提供可复现的分项能力评分和汇总能力指数。
5. 提供手动和受控低频定时运行、持久化历史、渠道摘要、详情页与 HTML 报告。
6. 保证新增策略和题目不要求修改执行器核心流程。

## 6. Non-goals

- 不自动暂停、删除、降权、切换渠道或修改生产负载均衡。
- 不做邮件、Webhook、短信或第三方通知系统。
- 不承诺黑盒行为探针可以识别完全自适应、已知全部探针的恶意中转。
- 不对所有 GPT 型号伪造同等强度的身份结论。
- 不把模型能力称作 IQ，不把身份风险和能力表现合成不可解释的单一结论。
- 不直接复制无明确许可证的代码或冻结基线。
- 首期不建设公开排行榜、云端题库服务或跨实例分布式调度。

## 7. 总体设计

新增 `backend-go/internal/modelaudit` 作为独立子系统，内部职责按需拆为：

```text
modelaudit
├── executor / protocol / profile
├── strategy / baseline
├── identity / mixture / capability
└── runner / scheduler / store / report / api
```

前端只提交经过校验的运行意图，不再自行模拟各家协议。快速测试、演武台和审计 Runner 共享执行器，但使用不同运行目的标记、超时、持久化和指标策略。所有审计请求直达选定渠道，禁止生产调度器改选其他渠道。

结果主键至少包含：稳定渠道 ID、渠道类型、请求协议、请求模型、实际模型、思考档位、请求轮廓、策略集版本和基线哈希。报告保存当时快照，不回读当前渠道配置来重写历史。

## 9. 风险与处理

| 风险 | 处理方式 |
| --- | --- |
| 行为指纹被渠道针对性伪造 | 使用轮换、多信号、跨轮次和分布证据，并明确威胁模型限制 |
| 参考基线授权不明 | 只实现导入合同；内置资产必须附来源、版本、哈希和授权记录 |
| 不同协议思考参数语义不一致 | 使用协议能力矩阵和显式映射；不支持时拒绝而非静默忽略 |
| 审计流量影响生产指标或封号 | 直达选定渠道、低频、抖动、预算限制，与生产健康状态隔离 |
| 默认模型变化破坏历史比较 | 每次运行保存请求模型和最终解析模型快照 |
| 评分被题库污染或版本漂移 | 题库版本化、轮换、保留判分器版本，不跨版本直接比较原始总分 |
| 自动判分产生错误权威感 | 优先确定性判分，展示样本、置信区间和不适用状态 |

## 10. 完成条件

- M1-M8 均达到各自最低验收条件，或由用户明确放弃。
- 五种协议的快速测试和演武台不再由前端各自拼装不完整请求。

- 渠道列表、详情页和 HTML 报告均能追溯策略版本、样本和置信度。
- 仅执行用户授权的不联网模拟验证；真实渠道、前端构建和完整项目验证由用户完成并反馈。

## 11. 阻塞和变更控制

出现以下情况必须停止并请求用户裁决：需要复制或发布无许可证资产；需要调用真实渠道；需要改变现有渠道 ID 或配置格式且无法无损迁移；官方协议与当前渠道私有协议存在不可兼容冲突；完成条件必须扩大到自动处置或外部告警。

用户确认后，本目录为 Goal 的权威方案。普通实现发现只更新 Status；只有 Outcome、边界、验收或任务账本发生实质变化时才修改本方案。
