# 验证、迁移与交接

## 1. 授权边界

用户授权 Codex 进行静态检查和不连接真实渠道的模拟测试。未经后续明确授权，不执行：

- 任何真实渠道、第三方模型或计费 API 请求。
- 全项目测试、完整前端 type-check、构建、打包或发布。
- 会修改外部系统、真实渠道状态或生产数据的验证。

允许的模拟验证应使用本地 mock server、`httptest`、固定响应夹具或纯函数测试；不得因名称是“测试”就意外读取真实配置密钥。

## 2. 验证分层

### 2.1 静态合同检查

- 协议能力矩阵和思考参数映射完整，没有未处理的默认分支。
- 新 API DTO 不泄露密钥，渠道关联使用稳定 ID。
- 策略、基线、题目和聚合器都有版本字段。
- 审计目的不调用生产健康、熔断、亲和性和促销更新入口。
- 新增 MDI 图标均在 `frontend/src/plugins/vuetify.ts` 注册。

### 2.2 模拟协议测试

为五协议建立可控上游，覆盖：成功非流式、成功流式、HTTP 错误、超时、取消、空正文、格式错误和断流。Responses 额外覆盖 completed、failed、incomplete、重复/乱序事件、正文 delta 与终态不一致、多轮 response ID；工具和图片协议覆盖结构化结果。

### 2.3 模拟审计测试

- 构造符合单一基线、固定替换、已知比例混合、OOD 和样本不足的数据。
- 验证策略启停、参数校验、版本冻结、基线哈希和置信度。
- 验证能力题的正确、部分正确、随机、格式错误、超时和不适用结果。
- 验证调度不重入、抖动范围、结束时间、停机错过不补跑、取消和预算终止。
- 验证报告摘要与冻结明细一致，HTML 不包含测试密钥或保留答案。

### 2.4 用户真实验收

由用户在自己的环境执行，至少选择：

- 一个已知可用 Responses/Codex 渠道，验证快速测试和多轮响应。
- Messages、Chat、Gemini 各一个可用渠道；Images 在用户接受费用时验证。
- 一个 GPT-5.6 Sol 目标执行手动身份审计。
- 两个渠道执行能力标准预设并检查分项与汇总。
- 一个短周期测试任务验证调度 UI；正式使用时恢复低频范围。

用户反馈真实结果后，只有属于本 Goal 范围的缺陷才进入修复；渠道自身不兼容必须记录协议轮廓或明确 unsupported，不能无限添加静默兜底。

## 3. 数据迁移

- 新审计表采用显式 Schema 版本和幂等迁移。
- 现有渠道 ID 直接复用；若发现历史渠道缺 ID，先通过现有配置迁移机制补齐并保存，再创建审计关联。
- 现有 Ping/健康数据不迁移为审计报告，因为语义不同。
- 旧前端快速测试入口在新执行器稳定后切换；不得长期保留两个行为不一致的隐藏执行路径。
- 新功能初始没有历史报告，渠道列表应显示“未检测”，不能用旧健康分伪造。

## 4. 实施与提交顺序

1. 先完成数据合同和协议执行器，确保快速测试与审计共享相同事实源。
2. 再建立策略、基线和题目框架，随后实现身份与能力算法。
3. 调度建立在可恢复 Runner 和持久化状态之上，不能先用进程内定时器临时拼接。
4. UI 最后消费稳定 DTO；可先提供最小诊断界面，但主线完成前必须替换全部旧快速测试入口。
5. 每个主线只运行其明确允许的模拟验证；已知失败必须在进入下一主线前修复或经用户裁决。

## 5. 回滚和失败处理

- 功能通过独立开关控制时，关闭只停止新任务，不删除历史。
- 数据迁移失败必须事务回滚并阻止服务使用不完整 Schema。
- 执行器遇到未知协议事件时保存脱敏证据并返回 protocol_error，不丢弃后假装成功。
- 基线或策略版本不兼容时拒绝生成正式报告，已有历史仍可读取。
- 评分重新计算必须生成新报告版本，不覆盖已展示的历史证据。

## 6. 全局完成证据

- M1-M8 的代码和 UI 产物存在，旧快速测试路径已按方案收敛。
- 获授权的静态检查和模拟测试结果已记录在 Status。
- 未运行的构建、全项目测试和真实渠道验收被明确列出。
- 用户拥有一份按协议和功能划分的真实验收清单。
- 没有真实密钥、无许可证参考资产或本地绝对参考路径进入发布配置。
- 工作区内 Goal 所属改动与用户其他改动可以明确区分。

## 7. 停止条件

需要真实 API 验证、需要复制无许可证资产、需要破坏性迁移、发现渠道 ID 无法稳定保持、或者官方协议和必须支持的私有协议需要用户选择时，停止当前主线并请求裁决。普通实现困难、首次模拟失败或仍有可验证替代路径不构成阻塞。
